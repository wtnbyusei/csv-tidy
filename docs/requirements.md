## 1. 目的と背景

CSV データを使いやすい形に整える Web アプリケーションを開発する。
主な目的は学習とポートフォリオであり、要件定義→設計→実装→テストという開発の過程をリポジトリに記録する。
このため、機能を広げることよりも、各段階の品質（テスト・ドキュメント・設計の説明しやすさ）を優先する。

### 1.1 変更の原則

このツールの目的はデータを整えることなので、データを変えること自体は目的に含まれる。そのうえで、利用者が気づかないうちにデータが変わることを防ぐため、次の3つを守る。すべての機能（v0.2 の列の操作、v0.3 の値の正規化を含む）は、この原則に沿って設計する。

1. **変更するのは、利用者が選んだ処理だけ。** 処理ごとにオン・オフでき、意味まで変えるおそれがある処理（重複行の削除など）は初期状態をオフにする。ただし、安全のための処理（数式の無害化、FR-49）は、何もしなくても安全な出力になるよう初期状態をオンにする。この処理もオフにでき、変更は差分表示で見せる。
2. **変更はすべて見せる。** どのセルをどう変えたか、どの行をなぜ削除したかを差分表示で確認できるようにする。警告の対象になる値（制御文字、列数の不一致など）は書き換えず、知らせるだけにする。
3. **元のファイルは書き換えない。** 整形の結果は別のファイル（`元の名前_tidy.csv`）として出力する。

## 2. 決定事項サマリ

| 項目 | 決定内容 |
| --- | --- |
| 提供形態 | Web アプリ（ブラウザから操作） |
| 主な利用者 | 開発者本人。ポートフォリオ（自分の技術力を示す作品集）として、採用担当者などが GitHub で見たり手元で動かしたりすることも想定する |
| 実装言語 | Python |
| 構成 | FastAPI（API）＋軽量フロントエンド（HTML/JS）。整形ロジックは Web に依存しない純 Python のコアとして分離する |

### 3.2 v0.1 のスコープ外

- 区切り文字の選択・自動判定（TSV など）
- ヘッダー行の有無の切り替え（1行目は常にヘッダーとして扱う）
- キー列を指定した重複判定（v0.2 の FR-65 で対応）
- 変更内容のレポートファイルの出力（件数の画面表示は FR-46 で範囲内とする）。v0.2 でも範囲外とし、v0.2 の後で決める
- 処理設定の保存と再利用。v0.2 でも範囲外とし、v0.2 の後で決める
- 10MB を超えるファイル、ストリーミング処理
- 認証、複数ユーザー対応、クラウドへのデプロイ
- FR-10 に挙げた以外の文字コード（UTF-16 など。Excel の「Unicode テキスト」形式の保存で使われる）
- 日本語以外の画面表示（多言語対応）
- NFR-10 に挙げた以外のブラウザ（Safari など）での動作確認

## 4. 機能要件（v0.1。v0.2 は 4.7 節）

### 4.1 ファイル入力

| ID | 要件 |
| --- | --- |
| FR-01 | ブラウザから CSV ファイルを1つアップロードできる |
| FR-02 | ファイルサイズの上限は 10MB（10×1024×1024 = 10,485,760 バイト）とする。ちょうど上限のファイルは受け付け、1バイトでも超えた場合は処理せずエラーを表示する |
| FR-03 | 区切り文字はカンマに固定し、RFC 4180 に準拠して解析する（ダブルクォートで囲まれたセル内のカンマ・改行・エスケープされた `""` を正しく扱う） |
| FR-04 | 最初の空でない行をヘッダー行として扱う。先頭にある空行（FR-21 の定義で空と判定される行）は飛ばし、出力にも含めない。飛ばした行数は情報として表示する |
| FR-05 | CSV の書き方として不正な箇所（クォートの閉じ忘れ、閉じたクォートの直後にカンマ・改行・`"` 以外の文字がある）を見つけたら処理を中止し、問題のあるレコードが始まる行番号を表示する。閉じ忘れはファイルの最後まで読んで初めて分かるため、「最後に正しく読めたレコードの次の行」を開始行として表示する |
| FR-06 | 1つのセルの長さは、ファイルサイズの上限（10MB）まで受け付ける（Python の `csv` モジュールの既定の上限 131,072 文字を引き上げる） |
| FR-07 | 複数行にまたがるセル（クォート内に改行を含むセル）がある場合は、エラーにはせず、情報として行番号を表示する。余分なクォートがたまたま対になって複数行が1つのセルにまとまってしまった場合、CSV の書き方としては正しいためエラーでは検出できず、この表示で気づけるようにする |
| FR-08 | 中身がないファイル（0 バイト、または空行だけのファイル）は「データがありません」というエラーにして処理を中止する。ヘッダー行だけのファイルはエラーにせず通常どおり処理し、ヘッダー行だけを出力する。このとき「データ行がありません」と情報を表示する |

### 4.2 文字コード・改行の正規化

| ID | 要件 |
| --- | --- |
| FR-10 | 入力の文字コードは UTF-8（BOM 付き・BOM なし）と CP932（Shift_JIS の Windows 拡張）の2種類を対象とする |
| FR-11 | 文字コードは UTF-8（BOM 付き）→ UTF-8 → CP932 の順に試して自動判定し、判定結果を画面に表示する |
| FR-12 | 利用者は判定結果を手動で上書きし、再読み込みできる |
| FR-13 | どの文字コードでもデコードできない場合はエラーを表示し、処理を中止する |
| FR-14 | 出力の文字コードは UTF-8 / UTF-8（BOM 付き、Excel 向け）/ CP932 から選べる。既定値は UTF-8 |
| FR-15 | 出力の改行コードは LF / CRLF から選べる。既定値は LF |
| FR-16 | 出力を CP932 にしたとき、CP932 で表せない文字（絵文字、`—`（U+2014）など）があれば、勝手に置換せず出力を中止する。件数と最初の 20 件（行・列・文字）を一覧で表示し、差分表示（FR-42）でも該当セルを強調して移動できるようにする。利用者は元データを直すか、UTF-8 出力に切り替えて対処する |
| FR-17 | デコードした結果に NUL 文字（U+0000）が含まれる場合は、CSV ではないファイルとみなして処理を中止する。ファイルの先頭が `PK\x03\x04`（ZIP 形式。xlsx ファイルが該当する）の場合は「Excel で CSV 形式として保存し直してください」と案内する |
| FR-18 | 次の文字が含まれる場合は、処理は続け、値も変更せずに警告する。(1) 制御文字: U+0001〜U+001F（タブ・CR・LF を除く）、DEL（U+007F）、C1 制御文字（U+0080〜U+009F。二重エンコードによる文字化けの手がかりにもなる）。(2) 見えない文字: ゼロ幅文字（U+200B〜U+200D、U+2060）と、ファイルの途中にある BOM（U+FEFF）。警告では件数と最初の 20 件（行・列・文字の種類）を表示し、差分表示では該当する文字を `[ZWSP]` のような記号で見える形にして強調する |

### 4.3 空白・空行・重複の除去

各処理は個別にオン・オフできる。初期状態は、空白トリムと空行の削除がオン、重複行の削除がオフとする（意図的な重複を誤って消さないため）。出力の前に行う数式の無害化（FR-49）は初期状態をオンとする。

| ID | 要件 |
| --- | --- |
| FR-20 | 空白トリム: 各セルの前後にある半角スペース（U+0020）、タブ（U+0009）、NBSP（U+00A0）、全角スペース（U+3000）を除去する。除去するのはここに挙げた文字だけとする。セル内部の空白は変更しない。ヘッダーと列数が異なる行にも適用する |
| FR-21 | 空行の削除: 列数にかかわらず、すべてのセルが空（トリムを有効にしている場合はトリム後の値で判定）の行を削除する。まったく何もない行（セル0個）もこれに含む。この判定は列数のチェックより先に行い、削除した行は列数の警告の対象にしない |
| FR-22 | 重複行の削除: 列数と全セルの値がすべて一致する行を重複とし、最初に現れた行を残して以降を削除する。値の比較はトリムなどの処理を適用した後の値で行う。セルが省略されている行（例: `a,b` → 2列）と、セルはあるが空の行（例: `a,b,,` → 4列）は、列数が違うため別の行として扱う。重複行の削除がオフのときも重複の判定は行い、「重複が N 件あります」という情報と、どの行がどの行と同じかを表示する（差分表示でも印を付ける）。利用者は内容を見てから削除するかを決められる |
| FR-23 | ヘッダー行は空行の削除と重複行の削除の対象外とする（トリムは適用する） |
| FR-24 | 処理は「デコード → 解析 → 空白トリム → 空行の削除 → 列数のチェック → 重複行の削除 → 数式の無害化 → エンコード」の順に適用する |
| FR-25 | 何も書かれていないセル（`a,,b` の2列目）とクォートで囲んだ空文字（`a,"",b` の2列目）は、どちらも空のセルとして扱い区別しない（RFC 4180 と Python の `csv` モジュールの解釈に従う） |

### 4.4 不正な行の扱い

| ID | 要件 |
| --- | --- |
| FR-30 | ヘッダーと列数が異なる行があっても処理は中止しない |
| FR-31 | そのような行は、列数を変えずに（空のセルを足したり削ったりせずに）出力し、画面に警告として元ファイルでの行番号と列数を表示する。トリムは FR-20 のとおり適用する |

### 4.5 プレビューと変更前後の比較

| ID | 要件 |
| --- | --- |
| FR-40 | アップロード後、読み込んだ内容を表形式でプレビューする |
| FR-41 | 差分は後から推測して計算するのではなく、整形処理の中で「どの行を、なぜ削除したか」「どのセルをトリムしたか」を記録し、それをもとに表示する |
| FR-42 | 変更前と変更後を左右に並べて表示する（VSCode や WinMerge の差分表示のような形）。行はテキストの行ではなく CSV のレコード単位で揃える |
| FR-43 | 削除した行は強調表示し、削除理由（「空行」「重複: N 行目と同じ」）を添える。トリムしたセルは、セル単位で強調表示する |
| FR-44 | 表示を「変更箇所のみ」（前後数行も含む）と「全行」で切り替えられる。既定は「変更箇所のみ」とし、前後の変更箇所へ移動できる。「全行」はページを分けて表示し、行数が多くても画面が重くならないようにする |
| FR-45 | セルが省略されている箇所（行の列数がヘッダーより少ない部分）は、空のセルと見た目で区別できるように表示する |
| FR-46 | 変更の件数（削除した空行の数、削除した重複行の数、トリムしたセルの数、列数の警告の数、無害化したセルの数）を表示する |
| FR-47 | 文字コードと改行コードの変換はファイル全体にかかる変更なので、行ごとではなく画面上部に「変換元 → 変換先」として表示する |
| FR-48 | 整形処理の前には先頭が `=` `+` `-` `@`（全角の `＝` `＋` `－` `＠` を含む）でなかったのに、処理の後に先頭がこれらの文字になったセル（例: トリムで `␣=1+1` が `=1+1` になる）を警告する。この警告では値は変更しない（無害化は FR-49 で行う）。該当するセルは差分表示で強調し、件数を FR-46 の件数表示に含める。元から先頭がこれらの文字だったセルは対象外とする |

### 4.6 出力

| ID | 要件 |
| --- | --- |
| FR-49 | 数式の無害化（CSV インジェクション対策）: 表計算ソフトで開いたときに数式として実行されないよう、出力するセル（ヘッダーを含む）のうち、先頭が `=` `+` `-` `@`、全角の `＝` `＋` `－` `＠`、タブ、CR、LF のいずれかで始まる値の先頭に `'`（シングルクォート）を付ける。ただし、数値としてそのまま読める値（`-5`、`+81`、`-1.5`、`-1e3` のように、符号・半角数字・小数点・指数だけからなる値）は数式にならないため対象外とする。初期状態はオンで、オフにできる。無害化した値は変更として記録し、差分表示で示す。Excel で保存し直すと `'` が外れて再び数式として扱われることがある点を README に書く（NFR-09） |
| FR-50 | 整形後の CSV をダウンロードできる。保存するファイルの初期の名前は、元のファイル名から拡張子を除いた部分に `_tidy.csv` を付けたものとする（例: `顧客一覧.csv` → `顧客一覧_tidy.csv`、`data.txt` → `data_tidy.csv`、拡張子がない `data` → `data_tidy.csv`）。名前はブラウザ側で付ける。保存先に同じ名前のファイルがあるときの扱い（`(1)` を付けるなど）はブラウザに任せる |

### 4.7 列の操作（v0.2）

左の設定欄に列の一覧を置き、出力する列の順番・名前・残すかどうかを「最終形」として指定する（画面設計書 7 章）。操作の履歴は持たない。

| ID | 要件 |
| --- | --- |
| FR-60 | 列の一覧: ヘッダーの列を、元の順番で一覧に表示する。列数がヘッダーより多い行がある場合は、ヘッダーにない列も「N 列目（ヘッダーなし）」として一覧に加える（いちばん列数の多い行の列数まで）。データを勝手に捨てないため、初期状態ではすべての列を出力する |
| FR-61 | 出力する列の選択: 列ごとに出力するかどうかを選べる。出力しない列は、出力のすべての行（ヘッダーを含む）から除く |
| FR-62 | 並べ替え: 一覧の順番を出力の列の順番とする。一覧の中で列を移動できる |
| FR-63 | 名前の変更: 出力するヘッダーの列名を書き換えられる。一覧と差分表示では、書き換えた列に元の名前を添える |
| FR-64 | 最初に戻す: 一覧の順番・名前・選択を、読み込んだときの状態に戻せる。別のファイルを読み込んだときも、読み込んだときの状態から始める |
| FR-65 | 重複の判定に使う列: 列ごとに「重複の判定に使う」かどうかを選べる。重複の判定（FR-22）は、選んだ列の値がすべて一致する行を重複とする。初期状態は、出力するすべての列とする。出力しない列も判定に使える（例: ID を出力に残したまま判定から外す、またはその逆）。セルがない（列数が足りない）ことと空のセルは区別する。1 列も選ばないときは重複の判定をしない。重複行を削除したときに残るのは最初の行で、判定に使わない列の値も最初の行のものが残る |
| FR-66 | 列名を整える: 出力するヘッダーを、次のあるべき姿にそろえる。H-1 すべての列に名前がある、H-2 名前が重複しない、H-4 名前にセル内の改行がない（H-3 の前後の空白は FR-20 で取り除く）。直し方は、(1) 改行（CR・LF・CRLF）を半角スペースに置き換える、(2) 空の名前を「列N」（N は元のファイルで何列目か）にする、(3) 同じ名前の 2 つ目以降に「_2」「_3」…を付ける（付けた結果がほかの列名と同じになるときは番号を進める）の順に行う。列の選択・並べ替え・名前の変更の後の、最終的なヘッダーに対して行う。初期状態はオンで、オフにできる。直した列名は変更として記録し、差分表示で示す。オフのときは、あるべき姿でない列名を警告する |
| FR-67 | 出力しない列のセルは、数式の無害化（FR-49）と CP932 で表せない文字の検査（FR-16）の対象にしない。文字の検査（FR-18）と列数の検査（FR-30）は、読み込んだファイル全体に対して行う。出力しない列のセルについての警告には「（出力しない列）」と添え、出力には関係しないことが分かるようにする |
| FR-68 | 差分表示: 左の表（変更前）は元の列の順番で、右の表（変更後）は出力する列の順番と名前で表示する。出力しない列は右の表に出さない（画面設計書 7.3） |
| FR-69 | 処理の順番: 「デコード → 解析 → 空白トリム → 空行の削除 → 列数のチェック → 重複行の削除（FR-65 で選んだ列で比べる）→ 列の選択・並べ替え・名前の変更 → 列名を整える → 数式の無害化 → エンコード」とする（FR-24 に列の操作を加えたもの） |

## 5. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 性能 | 10MB（約10万行×10列）の CSV で、アップロードしてから差分表示が出るまでが 5 秒以内であること。開発に使う PC で測定する。測定用のデータは生成スクリプトで作り、スクリプトをリポジトリに置く |
| NFR-02 | セキュリティ | サーバーは `127.0.0.1` のみで待ち受ける。アップロードされたデータはメモリ上だけで扱い、ディスクやログに内容を残さない |
| NFR-03 | 保守性 | 整形ロジック（コア）は FastAPI に依存させず、単体でテストできるようにする |

## 6. 受け入れ基準（v0.1。v0.2 は 6.1 節）

1. CP932 で保存された CSV をアップロードすると、文字コードが CP932 と判定される。UTF-8（BOM 付き）+ CRLF で出力したファイルは、先頭の 3 バイトが `EF BB BF`（BOM）で、改行がすべて CRLF になっている（自動テストで確認する）。さらに手動の確認項目として、このファイルを Excel で開いて文字化けしないことを確かめる。
2. `"  山田　"`（前後に半角と全角の空白）のセルが `山田` になり、`山田　太郎` のようなセル内部の空白は保たれる。
3. 空行とトリム後に空になる行が削除され、ヘッダー行は削除されない。
4. トリム後に全列が一致する2行のうち、1行目だけが残る。
5. 列数が不正な行を含む CSV でも処理が完了し、その行番号が警告として表示される。
6. 10MB を超えるファイルと、デコードできないファイルは、それぞれ分かりやすいエラーで拒否される。
7. 3行目でクォートを閉じ忘れた CSV は処理が中止され、エラーとして3行目が表示される。`"c"x,d` を含む行も、その行番号とともにエラーになる。`"Yes, I am"` のようにクォート内にカンマがあるセルは正しく1つのセルとして読まれる。
8. ヘッダーが4列の CSV で、`a,b`（2列）と `a,b,,`（4列）は重複として扱われない。`a,b` の行は列数の警告を受け、出力でも2列のままである。
9. 1000行の CSV の999行目だけが変更された場合でも、「変更箇所のみ」の表示でその行が表示され、変更の件数に反映される。
10. NUL 文字を含むファイルは拒否される。xlsx ファイルをアップロードすると、CSV として保存し直すよう案内される。
11. CP932 出力で絵文字を含むセルがあると出力が中止され、その行・列と件数が表示される。
12. セルの値が `<script>alert(1)</script>` の CSV を読み込んでも、スクリプトは実行されず文字列として表示される。
13. `␣=1+1`（先頭に半角スペース）のセルはトリム後に警告の対象になり、差分表示で強調される。元から `=1+1` や `-5` だったセルは警告されない。数式の無害化をオフにすると、値は `=1+1` のまま出力される。
14. ゼロ幅スペース（U+200B）だけが異なり見た目が同じ2行は、重複として削除されない。ゼロ幅スペースは警告され、差分表示で記号として見える。C1 制御文字や DEL を含むセルも警告される。
15. セルの前後にある NBSP（U+00A0）はトリムで除去され、U+0085 や U+2028 など FR-20 に挙げていない文字は除去されない。
16. 文字コードの判定結果を手動で別の文字コードに変更すると、その文字コードで読み込み直した結果が表示される。
17. トリム・空行の削除・重複の削除は、それぞれオフにすると、その処理だけが行われなくなる。
18. 10,485,760 バイトちょうどのファイルは受け付けられ、10,485,761 バイトのファイルはエラーになる。
19. 0 バイトのファイルと空行だけのファイルは「データがありません」というエラーになる。ヘッダー行だけのファイルは処理され、ヘッダー行だけが出力される。
20. 先頭に空行が 2 行あるファイルは、3 行目がヘッダー行として扱われ、「2 行を飛ばした」と表示される。出力には先頭の空行が含まれない。
21. 10MB（約10万行×10列）の CSV で、アップロードから差分表示までが 5 秒以内である（開発に使う PC で測定）。
22. 初期状態では重複行は削除されず、「重複が N 件あります」という情報と該当する行が表示される。重複行の削除をオンにすると、2件目以降が削除される。
23. `顧客一覧.csv` を整形してダウンロードすると、保存するファイルの初期の名前が `顧客一覧_tidy.csv` になる。
24. 初期状態で、`=1+1`、`@SUM(A1)`、`＝1+1`、`+81-90-1234-5678`、`- メモ` のセルは先頭に `'` が付いて出力され、無害化したことが差分表示と件数に表示される。ヘッダーも対象になる。`-5`、`+81`、`-1.5`、`-1e3` は変わらない。数式の無害化をオフにすると、どのセルも変わらない。

### 6.1 受け入れ基準（v0.2）

25. 列の一覧で列のチェックを外す、順番を入れ替える、名前を書き換えると、出力の列とヘッダーがそのとおりになる。差分表示の右の表も同じ順番と名前になる。「最初に戻す」で読み込んだときの状態に戻る。
26. ヘッダーが 4 列で 5 列の行がある CSV では、一覧に「5 列目（ヘッダーなし）」が出て、初期状態では出力に残る。
27. `ID,氏名,電話` で ID だけが違う 2 行は、初期状態では重複にならない。ID の「重複の判定に使う」を外すと重複になり、重複行の削除をオンにすると 2 行目が削除される。このとき ID は出力に残り、1 行目の ID の値が出力される。
28. 初期状態で、ヘッダー `名前,,名前,住所↵（番地）`（↵ はセル内の改行）は `名前,列2,名前_2,住所 （番地）` として出力され、差分表示に列名を整えたことが示される。列名を整える処理をオフにすると元のまま出力され、空・重複・改行を含む列名が警告される。
29. 列の操作をしていない（初期状態の）とき、ヘッダーがすでにあるべき姿の CSV の出力は、v0.1 と同じになる。

## 7. 仮定と未決事項

### 7.1 仮定（回答で直接決めていないため、暫定的に置いた内容）

- 「変更箇所のみ」の表示で前後に表示する行数は 3 行、「全行」表示の1ページの行数は 100 行とする。
