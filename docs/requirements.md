# csv-tidy 要件定義書

- 版: 第3版
- 作成日: 2026-09-24
- 更新日: 2026-09-25（第2版: レビュー指摘 H1〜H3 を反映 / 第3版: M1〜M4 を反映）
- 対象リリース: v0.1（MVP）。v0.2 以降は概要のみ記載

## 1. 目的と背景

CSV データを使いやすい形に整える Web アプリケーションを開発する。
主な目的は学習とポートフォリオであり、要件定義→設計→実装→テストという開発の過程をリポジトリに記録する。
このため、機能を広げることよりも、各段階の品質（テスト・ドキュメント・設計の説明しやすさ）を優先する。

## 2. 決定事項サマリ

| 項目 | 決定内容 |
| --- | --- |
| 提供形態 | Web アプリ（ブラウザから操作） |
| 主な利用者 | 開発者本人（学習・ポートフォリオ目的） |
| 実装言語 | Python |
| 構成 | FastAPI（API）＋軽量フロントエンド（HTML/JS）。整形ロジックは Web に依存しない純 Python のコアとして分離する |
| 実行環境 | ローカル実行のみ（クラウド公開はしない） |
| 操作フロー | アップロード → プレビュー → 処理選択・適用 → 変更前後の比較 → ダウンロード |
| 進め方 | MVP（v0.1）から機能を段階的に追加する |

## 3. スコープ

### 3.1 リリース計画

| 版 | 機能分類 | 内容 |
| --- | --- | --- |
| v0.1 | 文字コード・改行の正規化 | 入力文字コードの判定、出力文字コードと改行コードの選択 |
| v0.1 | 空白・空行・重複の除去 | セル前後の空白トリム、空行の削除、重複行の削除 |
| v0.2 | 列の操作 | 列の選択・並べ替え・リネーム・削除、ヘッダー名の正規化（詳細は未定） |
| v0.3 | 値の正規化 | 全角英数→半角、日付形式の統一、数値の桁区切りカンマの除去など（詳細は未定） |

### 3.2 v0.1 のスコープ外

- 区切り文字の選択・自動判定（TSV など）
- ヘッダー行の有無の切り替え（1行目は常にヘッダーとして扱う）
- キー列を指定した重複判定
- 変更内容のレポートファイルの出力（件数の画面表示は FR-46 で範囲内とする）
- 処理設定の保存と再利用
- 10MB を超えるファイル、ストリーミング処理
- 認証、複数ユーザー対応、クラウドへのデプロイ
- CSV インジェクション（`=` `+` `-` `@` で始まる値が表計算ソフトで数式として実行される問題）への対策。値は変更せず、警告も出さない（`-5` のような負の数も該当し、誤検知が多いため）

## 4. 機能要件（v0.1）

### 4.1 ファイル入力

| ID | 要件 |
| --- | --- |
| FR-01 | ブラウザから CSV ファイルを1つアップロードできる |
| FR-02 | ファイルサイズの上限は 10MB とする。超えた場合は処理せずエラーを表示する |
| FR-03 | 区切り文字はカンマに固定し、RFC 4180 に準拠して解析する（ダブルクォートで囲まれたセル内のカンマ・改行・エスケープされた `""` を正しく扱う） |
| FR-04 | 1行目は常にヘッダー行として扱う |
| FR-05 | CSV の書き方として不正な箇所（クォートの閉じ忘れ、閉じたクォートの直後にカンマ・改行・`"` 以外の文字がある）を見つけたら処理を中止し、問題のあるレコードが始まる行番号を表示する。閉じ忘れはファイルの最後まで読んで初めて分かるため、「最後に正しく読めたレコードの次の行」を開始行として表示する |
| FR-06 | 1つのセルの長さは、ファイルサイズの上限（10MB）まで受け付ける（Python の `csv` モジュールの既定の上限 131,072 文字を引き上げる） |
| FR-07 | 複数行にまたがるセル（クォート内に改行を含むセル）がある場合は、エラーにはせず、情報として行番号を表示する。余分なクォートがたまたま対になって複数行が1つのセルにまとまってしまった場合、CSV の書き方としては正しいためエラーでは検出できず、この表示で気づけるようにする |

### 4.2 文字コード・改行の正規化

| ID | 要件 |
| --- | --- |
| FR-10 | 入力の文字コードは UTF-8（BOM 付き・BOM なし）と CP932（Shift_JIS の Windows 拡張）の2種類を対象とする |
| FR-11 | 文字コードは UTF-8（BOM 付き）→ UTF-8 → CP932 の順に試して自動判定し、判定結果を画面に表示する |
| FR-12 | 利用者は判定結果を手動で上書きし、再読み込みできる |
| FR-13 | どの文字コードでもデコードできない場合はエラーを表示し、処理を中止する |
| FR-14 | 出力の文字コードは UTF-8 / UTF-8（BOM 付き、Excel 向け）/ CP932 から選べる。既定値は UTF-8 |
| FR-15 | 出力の改行コードは LF / CRLF から選べる。既定値は LF |
| FR-16 | 出力を CP932 にしたとき、CP932 で表せない文字（絵文字、`—`（U+2014）など）があれば、勝手に置換せず出力を中止する。件数と最初の 20 件（行・列・文字）を一覧で表示し、差分表示（FR-42）でも該当セルを強調して移動できるようにする。利用者は元データを直すか、UTF-8 出力に切り替えて対処する |
| FR-17 | デコードした結果に NUL 文字（U+0000）が含まれる場合は、CSV ではないファイルとみなして処理を中止する。ファイルの先頭が `PK\x03\x04`（ZIP 形式。xlsx ファイルが該当する）の場合は「Excel で CSV 形式として保存し直してください」と案内する |
| FR-18 | タブ・CR・LF 以外の制御文字（U+0001〜U+001F）が含まれる場合は、処理は続け、警告として件数と最初の出現位置（行・列）を表示する |

### 4.3 空白・空行・重複の除去

各処理は個別にオン・オフできる。

| ID | 要件 |
| --- | --- |
| FR-20 | 空白トリム: 各セルの前後にある半角スペース、タブ、全角スペース（U+3000）を除去する。セル内部の空白は変更しない。ヘッダーと列数が異なる行にも適用する |
| FR-21 | 空行の削除: 列数にかかわらず、すべてのセルが空（トリムを有効にしている場合はトリム後の値で判定）の行を削除する。まったく何もない行（セル0個）もこれに含む。この判定は列数のチェックより先に行い、削除した行は列数の警告の対象にしない |
| FR-22 | 重複行の削除: 列数と全セルの値がすべて一致する行を重複とし、最初に現れた行を残して以降を削除する。値の比較はトリムなどの処理を適用した後の値で行う。セルが省略されている行（例: `a,b` → 2列）と、セルはあるが空の行（例: `a,b,,` → 4列）は、列数が違うため別の行として扱う |
| FR-23 | ヘッダー行は空行の削除と重複行の削除の対象外とする（トリムは適用する） |
| FR-24 | 処理は「デコード → 解析 → 空白トリム → 空行の削除 → 列数のチェック → 重複行の削除 → エンコード」の順に適用する |
| FR-25 | 何も書かれていないセル（`a,,b` の2列目）とクォートで囲んだ空文字（`a,"",b` の2列目）は、どちらも空のセルとして扱い区別しない（RFC 4180 と Python の `csv` モジュールの解釈に従う） |

### 4.4 不正な行の扱い

| ID | 要件 |
| --- | --- |
| FR-30 | ヘッダーと列数が異なる行があっても処理は中止しない |
| FR-31 | そのような行は、列数を変えずに（空のセルを足したり削ったりせずに）出力し、画面に警告として元ファイルでの行番号と列数を表示する。トリムは FR-20 のとおり適用する |

### 4.5 プレビューと変更前後の比較

| ID | 要件 |
| --- | --- |
| FR-40 | アップロード後、読み込んだ内容を表形式でプレビューする |
| FR-41 | 差分は後から推測して計算するのではなく、整形処理の中で「どの行を、なぜ削除したか」「どのセルをトリムしたか」を記録し、それをもとに表示する |
| FR-42 | 変更前と変更後を左右に並べて表示する（VSCode や WinMerge の差分表示のような形）。行はテキストの行ではなく CSV のレコード単位で揃える |
| FR-43 | 削除した行は強調表示し、削除理由（「空行」「重複: N 行目と同じ」）を添える。トリムしたセルは、セル単位で強調表示する |
| FR-44 | 表示を「変更箇所のみ」（前後数行も含む）と「全行」で切り替えられる。既定は「変更箇所のみ」とし、前後の変更箇所へ移動できる。「全行」はページを分けて表示し、行数が多くても画面が重くならないようにする |
| FR-45 | セルが省略されている箇所（行の列数がヘッダーより少ない部分）は、空のセルと見た目で区別できるように表示する |
| FR-46 | 変更の件数（削除した空行の数、削除した重複行の数、トリムしたセルの数、列数の警告の数）を表示する |
| FR-47 | 文字コードと改行コードの変換はファイル全体にかかる変更なので、行ごとではなく画面上部に「変換元 → 変換先」として表示する |

### 4.6 出力

| ID | 要件 |
| --- | --- |
| FR-50 | 整形後の CSV をダウンロードできる。ファイル名は元の名前に `_tidy` を付けたもの（例: `data.csv` → `data_tidy.csv`・仮定） |

## 5. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 性能 | 10MB の CSV の処理が一般的なノート PC で数秒以内に終わる（目安） |
| NFR-02 | セキュリティ | サーバーは `127.0.0.1` のみで待ち受ける。アップロードされたデータはメモリ上だけで扱い、ディスクやログに内容を残さない |
| NFR-07 | セキュリティ | 画面に表示するセルの値は必ず HTML エスケープする（値を HTML として解釈させない）。悪意のある CSV を読み込んでもスクリプトが実行されないこと |
| NFR-08 | 構成 | サーバーは状態を持たない。アップロードしたファイルはブラウザ側で保持し、文字コードの上書きやオプションの変更のたびにファイルと設定を送り直す。サーバーは差分情報と出力ファイルをまとめて返し、「全行」表示のページ切り替えはブラウザ内で行う |
| NFR-03 | 保守性 | 整形ロジック（コア）は FastAPI に依存させず、単体でテストできるようにする |
| NFR-04 | テスト | コアはユニットテスト（pytest）、API は結合テストで検証する。境界条件（BOM、全角スペース、クォート内の改行、空ファイル、ヘッダーのみのファイル、不正な行）をテストケースに含める |
| NFR-05 | 再現性 | README の手順だけでセットアップと起動ができる |
| NFR-06 | 実行環境 | Python 3.12 以上（仮定） |

## 6. 受け入れ基準（v0.1）

1. CP932 で保存された CSV をアップロードすると文字コードが CP932 と判定され、UTF-8（BOM 付き）+ CRLF で出力したファイルを Excel で開いても文字化けしない。
2. `"  山田　"`（前後に半角と全角の空白）のセルが `山田` になり、`山田　太郎` のようなセル内部の空白は保たれる。
3. 空行とトリム後に空になる行が削除され、ヘッダー行は削除されない。
4. トリム後に全列が一致する2行のうち、1行目だけが残る。
5. 列数が不正な行を含む CSV でも処理が完了し、その行番号が警告として表示される。
6. 10MB を超えるファイルと、デコードできないファイルは、それぞれ分かりやすいエラーで拒否される。
7. 3行目でクォートを閉じ忘れた CSV は処理が中止され、エラーとして3行目が表示される。`"c"x,d` を含む行も、その行番号とともにエラーになる。`"Yes, I am"` のようにクォート内にカンマがあるセルは正しく1つのセルとして読まれる。
8. ヘッダーが4列の CSV で、`a,b`（2列）と `a,b,,`（4列）は重複として扱われない。`a,b` の行は列数の警告を受け、出力でも2列のままである。
9. 1000行の CSV の999行目だけが変更された場合でも、「変更箇所のみ」の表示でその行が表示され、変更の件数に反映される。
10. NUL 文字を含むファイルは拒否される。xlsx ファイルをアップロードすると、CSV として保存し直すよう案内される。
11. CP932 出力で絵文字を含むセルがあると出力が中止され、その行・列と件数が表示される。
12. セルの値が `<script>alert(1)</script>` の CSV を読み込んでも、スクリプトは実行されず文字列として表示される。

## 7. 仮定と未決事項

### 7.1 仮定（回答で直接決めていないため、暫定的に置いた内容）

- 「変更箇所のみ」の表示で前後に表示する行数は 3 行、「全行」表示の1ページの行数は 100 行とする。
- ダウンロードするファイル名には `_tidy` を付ける。
- 各処理（トリム・空行の削除・重複の削除）の初期状態はすべてオンとする。
- クォートされたセルの中の改行は変更せずに保持する（改行コードの選択はレコードの区切りにのみ適用する）。
- 出力時のクォートは必要なセルにだけ付ける（Python の `csv.QUOTE_MINIMAL` 相当）。
- 実行環境は Python 3.12 以上とする。

### 7.2 未決事項（v0.2 以降で決める）

- 列の操作の具体的な UI と操作単位
- 値の正規化の対象（日付フォーマットの種類、数値の判定ルールなど）
- 変更サマリレポートや処理設定の保存を追加するかどうか

要件は質問と回答の形式で決めた。選択肢と採用理由を記録する。

| # | 質問 | 採用 | 主な理由・トレードオフ |
| --- | --- | --- | --- |
| 1 | 提供形態 | Web アプリ | ブラウザで操作できる。UI の実装と配布の負荷は増える |
| 2 | 利用者 | 学習・ポートフォリオ目的 | 機能は小さく保ち、品質とドキュメントを重視する |
| 3 | 整形機能 | 4分類すべて | 範囲が広いため、#8 で段階リリースにした |
| 4 | 言語 | Python | 標準の `csv` モジュールが堅牢で、文字コードも扱いやすく、pytest でテストしやすい |
| 5 | 構成 | FastAPI＋軽量フロント | 層を分けることでテストと設計の説明がしやすい。Streamlit、Flask、Pyodide は採用しなかった |
| 6 | 実行環境 | ローカルのみ | 運用の負荷がない。公開すると悪用対策と費用が課題になる |
| 7 | 操作フロー | プレビュー付き | 変更前後を確認できる。サマリレポートと設定の保存は範囲外にした |
| 8 | 進め方 | MVP から段階追加 | 各段階で動くものを記録でき、手戻りの影響を小さくできる |
| 9 | 入力文字コード | 自動判定＋手動上書き | 対象を UTF-8 と CP932 に絞ることで誤判定を減らし、誤判定したときも利用者が直せる |
| 10 | 出力形式 | 文字コードと改行を選択式 | Excel 向けの BOM 付き UTF-8 と CP932 に対応するため |
| 11 | 重複の定義 | 全列一致・先頭を残す | v0.1 では単純さを優先した。キー列の指定は列の操作 UI が必要なので後回しにした |
| 12 | サイズ上限 | 10MB | メモリ上でまとめて処理でき、実装が単純になる |
| 13 | 空白トリム | 前後の半角・全角空白 | 日本語データでよく必要になる。セル内部の空白を縮めると意図しない変更になりうるため対象外とした |
| 14 | 区切り文字・ヘッダー | カンマ固定・1行目をヘッダー | テストケースと UI を最小限にするため |
| 15 | 不正な行 | 警告を表示してそのまま出力 | データを勝手に捨てないため |
| 16 | 成果物の置き場所 | `docs/` | 開発の過程を記録するという README の趣旨に合うため |
| 17 | 列数が合わない行の比較（レビュー H1） | 列数も含めてそのまま比較する | 末尾の空セルを無視して比較する案は、`a,b,,`（4列で空）と `a,b`（2列でセルなし）を同じに扱ってしまい、元から2列の行だと誤解させるため採用しなかった。画面でもセルがないことと空であることを見分けられるようにする |
| 18 | CSV の書き方の誤り（レビュー H2） | 厳密に解析してエラーで中止する | クォートの内側か外側かを追う状態機械で、閉じ忘れと閉じたクォート直後の不正な文字は検出できる。余分なクォートが対になっている場合は検出できないため、複数行にまたがるセルの情報表示で補う |
| 19 | 変更前後の比較（レビュー H3） | 変更を記録し、左右に並べて表示する | 先頭50行のプレビューでは後方の変更が見えない。行単位の汎用的な差分計算は、セル内の改行でずれるうえに推測になるため、処理中に記録した変更をもとに正確に表示する。件数の表示も追加の手間がほとんどないため範囲内とした |
| 20 | CSV ではないファイル（レビュー M1） | NUL はエラー、その他の制御文字は警告 | xlsx（ZIP 形式）は UTF-8 として、PNG は CP932 として読めてしまうことを確認した。いずれも NUL を含むため、NUL を判定の手がかりにした。古いシステムの出力に混ざる 0x1A などで止まらないよう、それ以外は警告にとどめた |
| 21 | CP932 に変換できない文字（レビュー M2） | 出力を中止し、件数・最初の20件・差分表示での強調 | 件数が多くても画面があふれず、場所もたどれる。置換オプションは「データを勝手に変えない」方針の例外になるため採用しなかった |
| 22 | データの保持場所（レビュー M3） | ブラウザ側（サーバーは状態を持たない） | ローカル実行のため通信量は問題になりにくく、有効期限やメモリ解放などの状態管理が不要でテストも単純になる |
| 23 | CSV インジェクション（レビュー M4） | 範囲外（値は変更せず、警告も出さない） | 負の数なども該当して誤検知が多く、整形ツールとしてデータを変えない方針と一致する。画面表示の HTML エスケープは必須要件（NFR-07）とした |
